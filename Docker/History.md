## История и основы Docker

Цель этой папки — **хранить все личные заметки о Docker**: краткую теорию, шпаргалки по командам и примеры конфигураций.

---

## Что такое Docker

**Docker** — это платформа для упаковки приложений в **контейнеры** и их запуска на любой машине, где установлен Docker Engine.

- **Контейнер** — это изолированное окружение, в котором приложение запускается вместе со всеми необходимыми зависимостями (библиотеки, утилиты, конфигурация).
- Контейнеры разделяют ядро операционной системы, поэтому они:
  - запускаются быстрее, чем виртуальные машины;
  - занимают меньше места;
  - легко переносятся между серверами и разработческими машинами.

Типичная цель Docker — сделать так, чтобы приложение **одинаково работало** на компьютере разработчика, на сервере тестирования и в продакшене.

## Краткая история появления и развития Docker

1. **До Docker**  
   Идеи контейнеризации существовали давно:  
   - в Linux были `chroot`, затем LXC (Linux Containers);  
   - в BSD — jails;  
   - в Solaris — zones.  
   Но эти технологии были сложны в настройке и не имели удобного, массового инструмента для разработчиков.

2. **2013 год — рождение Docker**  
   - Компания **dotCloud** (PaaS‑провайдер) представила проект Docker на конференции PyCon.  
   - Автор и один из основателей — **Solomon Hykes**.  
   - Изначально Docker использовал LXC, позже перешёл на собственный контейнерный рантайм.

3. **Открытый исходный код и быстрый рост**  
   - Docker был опубликован как **open‑source**‑проект на GitHub.  
   - Сообщество и компании быстро приняли Docker, потому что он упростил упаковку и развёртывание приложений.  
   - Появилась компания **Docker Inc.**, сосредоточенная на развитии экосистемы.

4. **Стандартизация контейнеров**  
   - Для избежания фрагментации была создана **Open Container Initiative (OCI)**.  
   - Были стандартизированы:
     - **формат образа** контейнера;
     - **интерфейс рантайма**.  
   Это позволило использовать одни и те же образы с разными рантаймами (например, containerd, runc).

5. **Интеграция с оркестраторами**  
   - Docker стал де‑факто стандартом для контейнеров.  
   - Появились оркестраторы: Docker Swarm, Kubernetes, Nomad и др.  
   - **Kubernetes** стал основным инструментом для управления кластерами контейнеров (масштабирование, обновления, отказоустойчивость).

6. **Современное состояние**  
   - Docker остаётся одним из самых популярных инструментов контейнеризации.  
   - Его используют:
     - разработчики (локальная разработка и тестирование);  
     - DevOps‑инженеры (CI/CD и деплой);  
     - компании любого масштаба.  
   - Помимо Docker, существуют и другие реализации контейнеров, но формат Docker‑образов и Dockerfile стал индустриальным стандартом.

## Основные понятия Docker

- **Образ (image)**  
  - Неизменяемый шаблон с файловой системой и метаданными.  
  - На основе образа запускаются контейнеры.  
  - Образы состоят из слоёв (layers), что экономит место и ускоряет загрузку.

- **Контейнер (container)**  
  - Запущенный экземпляр образа.  
  - Имеет собственную файловую систему, процессы, сетевой стек и порты.

- **Регистр (registry)**  
  - Хранилище образов (удалённый репозиторий).  
  - Примеры: **Docker Hub**, GitHub Container Registry, GitLab Registry, частные реестры компаний.

- **Docker Engine**  
  - Серверная часть, которая управляет образами и контейнерами.  
  - Взаимодействует с пользователем через CLI (`docker`).

## Docker Hub и готовые образы

**Docker Hub** — это публичный (с возможностью приватных репозиториев) реестр Docker‑образов по адресу `https://hub.docker.com`.

- На Docker Hub можно:
  - искать готовые образы (`ubuntu`, `nginx`, `mysql`, `postgres`, `redis` и др.);
  - брать **официальные образы** (помечены как *Official Image*);
  - публиковать свои образы.

### Примеры использования

- **Поиск образа:**

```bash
docker search nginx
```

- **Загрузка (pull) образа:**

```bash
docker pull nginx:latest
```

- **Запуск контейнера:**

```bash
docker run --name my-nginx -p 8080:80 nginx:latest
```

После этого nginx будет доступен в браузере по адресу `http://localhost:8080`.

## Dockerfile — описание образа

**Dockerfile** — это текстовый файл с инструкциями, которые описывают, как собрать образ.

Типичные инструкции:

- `FROM` — базовый образ;
- `WORKDIR` — рабочая директория внутри контейнера;
- `COPY` / `ADD` — копирование файлов в образ;
- `RUN` — выполнение команд при сборке (установка пакетов, сборка проекта);
- `EXPOSE` — документирование порта приложения;
- `CMD` или `ENTRYPOINT` — команда, которая будет запущена при старте контейнера.

### Пример простого Dockerfile для Python‑приложения

```dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["python", "main.py"]
```

- Сборка образа:

```bash
docker build -t my-python-app .
```

- Запуск контейнера:

```bash
docker run --rm -p 8000:8000 my-python-app
```

## Docker Compose — запуск нескольких сервисов

**Docker Compose** — это инструмент для описания и запуска **набора** контейнеров как одного приложения.

- Конфигурация хранится обычно в файле `docker-compose.yml`.
- Внутри описываются:
  - **services** — отдельные контейнеры (например, приложение и база данных);
  - сети, тома, переменные окружения, порты и т.д.

### Минимальный пример `docker-compose.yml`

```yaml
version: "3.9"

services:
  app:
    image: my-python-app
    build: .
    ports:
      - "8000:8000"
    depends_on:
      - db

  db:
    image: postgres:16
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: mydb
    volumes:
      - db_data:/var/lib/postgresql/data

volumes:
  db_data:
```

- Запуск всего стека:

```bash
docker compose up
```

- Остановка:

```bash
docker compose down
```
