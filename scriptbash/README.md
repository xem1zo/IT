# Repo Sync Copy (git pull + копирование содержимого)

Этот мини-проект содержит два скрипта (Bash и PowerShell), которые:

1. Выполняют `git pull` внутри *исходного* локального репозитория.
2. Копируют содержимое исходного репозитория в *целевой* локальный репозиторий:
   - исключая каталог `.git`
   - проверяя существование обоих путей
   - заменяя в целевом репозитории файлы/папки, имеющие те же имена, что и элементы из источника
3. Опционально выполняют `git push` из целевого репозитория после копирования.

## Файлы

- `sync_pull_copy_to_repo.sh` – реализация на Bash
- `sync_pull_copy_to_repo.ps1` – реализация на PowerShell
- `README.md` – этот файл

## Детали поведения

Для каждого элемента верхнего уровня внутри исходного репозитория (включая скрытые файлы, например `.env`) скрипт:

- пропускает запись `.git`
- удаляет соответствующую запись в целевом репозитории (если она существует)
- копирует элемент из источника в целевой репозиторий

Это означает, что лишние файлы/папки, существующие только в целевом репозитории, останутся нетронутыми.

## Использование (Bash)

```bash
./sync_pull_copy_to_repo.sh --source "/путь/к/repoA" --dest "/путь/к/repoB" [--remote origin] [--branch main] [--push]
```

Опционально:

- `--no-git-check` – пропустить проверку наличия каталогов `.git`
- `--wait` – показать паузу с запросом в конце (полезно при двойном щелчке)

Если вы запускаете из оболочки Unix, возможно, потребуется сделать скрипт исполняемым:

`chmod +x sync_pull_copy_to_repo.sh`

Примеры:

```bash
# Выполнить pull в исходном репозитории и скопировать в целевой
./sync_pull_copy_to_repo.sh --source "./repoA" --dest "./repoB"

# Выполнить pull из определённого удалённого репозитория/ветки, а затем выполнить push в целевом
./sync_pull_copy_to_repo.sh --source "./repoA" --dest "./repoB" --remote origin --branch main --push
```

## Использование (PowerShell)

```powershell
.\sync_pull_copy_to_repo.ps1 -SourcePath "C:\путь\repoA" -DestPath "C:\путь\repoB" [-Remote origin] [-Branch main] [-Push] [-NoGitCheck] [-Wait]
```

Примеры:

```powershell
# Выполнить pull в исходном репозитории и скопировать в целевой
.\sync_pull_copy_to_repo.ps1 -SourcePath "C:\repoA" -DestPath "C:\repoB"

# Выполнить pull из определённой ветки, а затем выполнить push в целевом
.\sync_pull_copy_to_repo.ps1 -SourcePath "C:\repoA" -DestPath "C:\repoB" -Remote "origin" -Branch "main" -Push
```

## Аутентификация / приватные репозитории (необязательная обработка)

Если какой-либо из репозиториев является приватным, команды `git pull` / `git push` могут потребовать учётные данные (SSH‑ключи, диспетчер учётных данных Windows или интерактивный запрос).

Скрипты не пытаются «обходить» аутентификацию; они будут выдавать сообщение об ошибке от `git`, чтобы вы могли настроить права доступа.

## Тестирование в Docker / WSL / виртуальной машине

1. Установите `git` в целевой среде.
2. Клонируйте два репозитория: ваш *исходный* и *целевой*.
3. Отредактируйте команды и пути, которые вы будете запускать внутри этой среды.
4. Запустите соответствующий скрипт:
   - Bash в Ubuntu/WSL/Docker
   - PowerShell в виртуальной машине Windows
5. Убедитесь, что файлы в целевом репозитории изменились должным образом и что (опциональный) push выполнился успешно.
